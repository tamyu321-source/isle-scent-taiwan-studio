# VECTOR / Perception Studio

A working React / TypeScript / Three.js portfolio application for 3D perception annotation and data production.

**Live demo:** https://tamyu321-source.github.io/isle-scent-taiwan-studio/vector/

## 五分鐘展示流程

1. 在城市路口旋轉、縮放場景，切換透視、俯視、前視；切換點雲、Mesh、邊界框、軌跡和地面網格。
2. 點擊 VEH-001，編輯位置、尺寸與方向。按 G 後拖曳物件，或用 B 框選多個物件，批次覆核。新增與刪除均可復原。
3. 播放 120 影格序列，拖曳時間軸；標註跟隨物件軌跡移動。
4. 打開「品質檢查」，定位低信心值、遮擋或未覆核物件。修改幾何屬性會取消先前的覆核。
5. 在任務頁拖曳排序（亦提供鍵盤可操作的上下按鈕），變更狀態。未完成覆核的場景不能標記為完成。
6. 查看分析圖與操作日誌，匯出 JSON / CSV，列印 PDF 報告，重新匯入 JSON。重新整理後，本機修改仍保留。

## Architecture

- `components/vector-workspace.tsx`: workspace navigation, keyboard interactions, inspector, dialogs and exports.
- `components/vector-viewport.tsx`: Three.js rendering lifecycle, deterministic geometry, camera, picking and dragging. Object labels project actual 3D coordinates into the viewport.
- `hooks/use-vector-project.ts`: local persistence, coalesced edit history, role-aware mutations and task transitions.
- `components/vector-panels.tsx`: production queue, analytics, rule-based quality review and activity stream.
- `lib/vector-model.ts`: data contracts, import validation, synthetic scene initialization and trajectory model.
- `tests/vector.test.mjs`: round-trip validation, rejected imports, quality rules and trajectory invariants.

The renderer updates per frame without asking React to rerender the point cloud. Scene geometry is deterministic, shared by the current scene, and freed when the scene changes. Object geometries update only when annotations change; frame playback changes transforms. FPS and point count are measured in the running viewport, not hard-coded performance claims.

## Data semantics and limits

This is a **static, device-local portfolio demonstration**. All scenes, coordinates, confidence scores and tracks are synthetic. No pretrained perception model, real driving dataset, vehicle control or production inference service is connected. Scene names are illustrative labels, not captured geographic locations.

Annotations are **track-level**, with position anchored at frame 042. Frame positions are generated by a constant-speed heading model; editing the anchor or heading changes the whole track. It is not an independent per-frame/keyframe annotation system. Ground dragging edits X/Z; height and dimensions are edited in the inspector. The mesh layer is generated box geometry, not imported CAD or glTF assets. Imports accept this application's JSON project schema, not arbitrary PCD/PLY point-cloud files.

The project is stored under `vector-perception-v1` in localStorage. No records are sent to a server. Save failures are shown; use JSON export to keep a portable backup. Imports are limited to 2 MB / 200 objects per scene and reject invalid numeric values, duplicate IDs and unsupported schemas. CSV contains all tracks across all three scenes. PDF output uses the browser print dialog. Undo history is kept for the current tab session; project data and the last 100 logs persist locally.

Role selection demonstrates interface rules only. It is **not authentication or a security boundary**. In a production integration the same authorization must run on a backend, with authenticated principals, concurrent edit revisions, an immutable audit log and a real dataset store. No backend API integration or team synchronization is claimed. There is no real visitor PV/UV analytics collection.

## Run and verify

Use Node 24 (this repository requires Node >=22.13):

```powershell
volta run --node 24.11.1 npm ci
volta run --node 24.11.1 npm run dev
# http://localhost:5173/vector
volta run --node 24.11.1 node --experimental-strip-types --test tests/vector.test.mjs
volta run --node 24.11.1 npx tsc --noEmit
```

GitHub Actions builds the static export, prepares the repository base path, runs the existing portfolio browser release gate, and deploys to GitHub Pages. VECTOR model checks run in the same workflow. See the release verification evidence for the actual browser cases executed on this revision.
